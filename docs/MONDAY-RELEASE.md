# Monday client demonstration release

One integrated review build combines Justin's screens (companion c108399) and Odoo migration fixes (e54466e) with Jodi's attendance API, staff readback, guided Companion actions and an encrypted attendance-only retry queue.

This branch is synthetic test-only. Device pairing is not production member or guardian authentication. Demo mode and connected-test mode are mutually exclusive. No payment, rank, email, or SMS writes are enabled.

## Demonstration
1. Pair a kiosk browser and a separate staff browser using private keys generated by the seed script.
2. On the kiosk choose the live session, identify the permitted student, confirm and verify the backend receipt.
3. Reload that student's Member 360 in the staff browser. The last check-in must match Odoo.
4. Open Guided Companion, read the real attendance summary, review the proposed internal task, then approve it. Verify the task in Odoo. This is explicitly rules-based, not a claimed generative AI call.
5. With a second student selected, disconnect the kiosk network. Confirm: display pending sync, never checked in. Reconnect with the kiosk open. The original key is retried, and the staff view must show one new attendance.

## Offline boundaries
The queue is encrypted with a device-local non-extractable key. It retains only command identifiers, timestamps and encrypted command payloads, never names or credentials. Only attendance is accepted. Up to 32 requests persist for up to eight hours. Replay requires the same authenticated device scope and passes all backend checks again. A closed class, expired authorization or stale version does not become success. No cold-start offline shell or background-while-closed guarantee is made. The saved attendance time is the server acceptance time, not an invented offline timestamp.
